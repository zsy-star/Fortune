# 中奖判定规则说明

本阶段已实现“命中 / 未中 / 不支持”判断，并在已支持玩法上增加基础中奖金额第一阶段：命中项按投注金额 × 赔率计算，未中、不支持、未配置赔率均为 0。当前不写客户余额、不生成余额流水、不做真实兑奖入账；返水如当前规则可计算，也只是结算统计项 / 快照字段，不代表真实收款或付款。

调用方必须显式传入一张订单和指定的一期开奖结果。结算服务不会自动选择最新开奖，避免把订单匹配到不确定期号。

## 返水统计快照

当前已在结算预览、正式结算快照、订单详情和结算历史中展示返水统计：

1. 投注本金 / 有效投注额：使用当前订单明细金额合计，不修改订单保存口径。
2. 中奖金额：沿用现有命中项 `投注金额 x 赔率` 公式，不重新计算旧快照，不改命中规则。
3. 返水比例：优先读取申报人绑定的赔率 / 返水方案；没有绑定时读取默认方案；玩法没有返水配置时按 0 计算。
4. 返水金额：按每条订单明细分别计算，`明细返水金额 = 明细投注金额 x 返水比例`，再汇总为 `total_rebate_amount`。
5. 命中、未中和 unsupported 明细都按有效投注金额参与返水统计；unsupported 明细若能按原投注类型找到返水配置则计算，否则按 0。
6. 统计结算金额：`statistic_net_amount = total_payout_amount + total_rebate_amount - total_bet_amount`。
7. 返水金额和统计结算金额只是结算快照 / 记账统计参考，不入账、不付款、不生成客户余额、不代表真实收款或付款。

正式结算 `result_snapshot.summary` 保存 `total_bet_amount`、`total_payout_amount`、`total_rebate_amount`、`statistic_net_amount`；每条 item 保存 `rebate_rate`、`rebate_amount`、`rebate_note`。旧快照没有这些字段时，界面显示旧记录提示或 0.00，不影响查看。

## 多生肖 / 连肖第一批结算口径

本阶段只使用开奖特码号码：

1. 将开奖特码号码按 `domain.zodiac_rules` 转为开奖特码生肖。
2. 将投注内容解析为生肖列表，支持 `马蛇`、`马,蛇`、`马，蛇`、`马、蛇` 等明确格式。
3. 如果开奖特码生肖在投注生肖列表中，则命中；否则未中。
4. 如果投注内容无法解析为至少两个不同生肖，则该明细标记为暂不支持。
5. 不计算连中几个；中奖金额只按命中项投注金额 × 匹配赔率计算；返水另作为统计快照项，不处理余额、佣金或真实盈亏。

连肖录单金额口径已按参考软件对齐：明确连肖语义的输入保存为一条汇总明细，`订单总额 = 金额`，不按生肖个数相乘，也不按生肖下对应号码数相乘。普通多生肖 / 特码生肖仍按既有解析模式计金额；特肖模式和各->各肖开关不受本规则影响。

结算快照会记录每条明细的开奖特码号码、开奖特码生肖、投注生肖列表、命中生肖（如有）和暂不支持原因（如有）。

## 复杂玩法第二批结算口径

本阶段继续只判断命中 / 未中 / 暂不支持；已支持玩法会记录基础赔率、中奖金额与返水统计快照，但不写余额、不处理佣金或真实盈亏。

### 连尾

1. 使用全部开奖号码：6 个正码 + 特码。
2. 将全部开奖号码转换为尾数。
3. 将投注内容解析为尾数列表，支持 `1尾,2尾`、`尾1 尾2`、`12` 等明确格式。
4. 如果投注尾数全部出现在开奖号码尾数中，则命中；否则未中。
5. 尾数必须为 0-9，否则该明细标记为暂不支持。

快照记录 `draw_numbers`、`draw_tails`、`selected_tails`、`matched_tails`。

### 平尾

1. 支持显式 `平尾` 语义，例如 `平尾 1,3,4,6 各1000`、`平尾 1-3-4-6 各1000`、`1,3,4,6 平尾 各1000`、`1-3-4-6平尾1000`。
2. 尾数必须为 0-9；重复尾数会去重并排序。
3. 订单总额按尾数个数计算：`总额 = 每尾金额 × 尾数个数`。
4. 保存为一条汇总明细，`selection` 使用稳定尾数列表，如 `1,3,4,6`；不展开为普通号码。
5. 正式结算只看 6 个正码尾数，不看特码尾数。
6. 投注尾数命中任一正码尾数则 hit；没有任何投注尾数出现在正码尾数中则 miss。
7. 快照记录 `draw_regular_numbers`、`selected_tails`、`matched_tails`、`payout_amount`、`rebate_amount` 等字段；不写余额、不入账。

### N不中 / 不中

1. 使用全部开奖号码：6 个正码 + 特码。
2. 将投注内容解析为号码列表，号码必须在 01-49。
3. 如果投注号码全部没有出现在开奖号码中，则命中。
4. 只要任意投注号码出现在开奖号码中，则未中。
5. 录单金额按整组金额保存，`N不中 08,09,10 各100`、`不中 08,09,10 各100`、`5不中 08,09,10,11,12 各100` 的订单总额均为 100，不按号码个数相乘。
6. 赔率匹配优先使用 `N不中`，没有该配置时回退 `不中`。

快照记录 `result`、`draw_numbers`、`selected_numbers`、`hit_numbers`、`odds`、`payout_amount`、`payout_note`、`unsupported_reason` 等字段。

### 几中几复选 / 连肖复选

1. 几中几复选支持号码列表 + `复N`，例如 `复3 01,02,03,04 各10`、`01,02,03,04 复3 各10`、`几中几复选 01,02,03,04 复3 各10`。
2. 连肖复选支持生肖列表 + `复N`，例如 `兔狗虎蛇龙 复4 各10`、`兔、狗、虎、蛇、龙 复4 各10`、`复4 兔狗虎蛇龙 各10`。
3. 订单总额按组合数计算：`总额 = 每组金额 × C(n,k)`。例如 4 个号码复 3 各 10，总额为 40；5 个生肖复 4 各 10，总额为 50。
4. 不展开成多条明细，保存为一条汇总明细；`selection` 保存标准号码或生肖列表，复选类型通过明细备注保存为 `复选类型=复N`。
5. 几中几复选正式结算第一阶段只开放 `复2` 和 `复3`：`复2` 动态展开为二中二组合，`复3` 动态展开为三中三组合；只看 6 个正码，不看特码。
6. 任一展开组合命中则订单项 hit；快照记录 `selected_numbers`、`selected_groups`、`matched_groups`、`fuxuan_type`。
7. 连肖复选由于缺少参考软件中奖样例，正式结算仍为 unsupported，`unsupported_reason` 为 `复选类玩法结算规则待确认`。

### 二中二 / 三中三 / 三中二

1. 支持前缀、括号组合和后缀写法，例如 `二中二 01,02 各10`、`二中二 (01-02)-(03-04) 各10`、`01,02二中二10`、`三中三 (01-02-03) 各10`、`三中二 (01-02-03) 各10`。
2. 二中二支持拖式 / 分组组合写法，例如 `二中二 01,02,03 拖 04,05,06 各5`、`二中二 01,02,03/04,05,06 各5`；左组 × 右组展开为无序二码组合，仍保存为二中二。
3. 二中二每组必须 2 个号码；三中三、三中二每组必须 3 个号码。号码必须在 01-49，单组内不允许重复；拖式两组之间也不允许重复号码。
4. 单组总额等于金额；多组或拖式总额等于金额乘以组合组数。
5. 保存为一条汇总明细，`selection` 使用稳定括号格式，如 `(01-02)`、`(01-02)-(03-04)`、`(01-02-03)`；明细备注保存 `连码组合数=N;连码组大小=K` 或 `拖式组合数=N;连码组大小=2`。
6. 正式结算只看 6 个正码，不看特码。
7. 二中二：每组 2 个号码都在正码中则该组 hit。
8. 三中三：每组 3 个号码全部在正码中则该组 hit，只中 2 个仍 miss。
9. 三中二：每组 3 个号码至少 2 个在正码中则该组 hit，中 3 个也 hit。
10. 任一组合 hit 则订单项 hit；快照记录 `selected_groups`、`matched_groups`、`draw_regular_numbers`、赔率、中奖金额和返水金额。

### 六肖中特

1. 使用开奖特码号码对应的生肖。
2. 当前严格要求投注内容为 6 个不同生肖。
3. 如果特码生肖在投注生肖列表中，则命中；否则未中。
4. 非法生肖或生肖数量不是 6 个时，该明细标记为暂不支持。

快照记录 `draw_special_number`、`draw_special_zodiac`、`selected_zodiacs`、`matched_zodiac`。

### 平码

1. 只使用 6 个正码，不包含特码。
2. 投注内容可包含一个或多个 01-49 号码。
3. 如果任意投注号码出现在 6 个正码中，则命中；否则未中。

快照记录 `draw_regular_numbers`、`draw_special_number`、`selected_numbers`、`matched_numbers`。

### 包半波

1. 使用开奖特码号码。
2. 计算特码波色、单双、大小。
3. 合法投注组合为：红单、红双、蓝单、蓝双、绿单、绿双、红大、红小、蓝大、蓝小、绿大、绿小。
4. 如果特码匹配任一投注组合，则命中；否则未中。

快照记录 `draw_special_number`、`draw_special_wave`、`draw_special_odd_even`、`draw_special_big_small`、`selected_halfwaves`、`matched_halfwave`。

## 需要确认的业务口径

1. 解析器展开后的“纯数字”是否永远表示特码号码投注，还是有时表示平码或全号命中。
2. 连肖复选、正码特、特串仍需要参考软件中奖样例确认正式结算口径。
3. 独立名义的胆拖、组选、全包不作为本阶段独立投注类型；当前已按复选、连码组合或二中二拖式 / 分组组合覆盖规则明确的底层能力。
4. 头数是否需要开放 `0头`，本阶段为兼容 `01-09` 的头数规则已支持。
5. 当前基础中奖金额只读取设置中心赔率配置；命中项按投注金额 × 赔率计算，未命中、不支持或未配置赔率为 0。返水只作为统计快照，不进入余额、流水或真实付款。
