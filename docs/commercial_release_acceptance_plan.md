# FORTUNE 正式商用前验收清单

本文档用于发布前全链路验收。验收目标是确认 FORTUNE 在当前产品范围内满足单机商用使用要求；本文不是新功能设计，不要求接入客户余额、真实付款或真实打印机。

## 1. 验收目标

本验收用于确认以下能力是否满足发布要求：

- 单机记账、号码录入、订单统计。
- 开奖核对、是否中奖查看。
- 中奖金额统计、返水统计、统计结算金额。
- 订单导入、拆单助手、导出对账。
- 调单快照、操作日志、备份恢复。
- 打印文本生成、复制、导出。

本验收不覆盖也不要求以下能力，因为它们不属于当前产品范围：

- 客户账户、客户余额、余额流水。
- 真实付款、真实收款、真实兑奖入账。
- 真实打印机调用、打印机驱动适配、静默打印、打印模板编辑器。
- 云同步 / 在线账号。

换句话说，FORTUNE 不做客户账户、不做客户余额、不做余额流水、不做真实兑奖入账，也不涉及真实资金支付。

## 3. 验收前准备

建议先执行：

```powershell
git status --short
python -m pytest -q
python scripts\pre_release_check.py --project-root .
python -m alembic heads
python scripts\check_db_migration_state.py data\fortune.db
```

说明：

- `git status --short`：只读，确认工作区是否干净。
- `python -m pytest -q`：测试会使用测试库；不得连接唯一真实库。
- `python scripts\pre_release_check.py --project-root .`：只读自检。
- `python -m alembic heads`：只读查看迁移 head。
- `python scripts\check_db_migration_state.py data\fortune.db`：只读检查真实库迁移状态；执行前建议备份真实库。

## 5. 导入验收样例

样例文件：`docs/samples/import_orders_sample.csv`。

覆盖：

- txt 导入：将 `docs/samples/order_entry_samples.txt` 中非注释行另存为 txt，确认可预览。
- csv 导入：使用 `docs/samples/import_orders_sample.csv`。
- xlsx 导入：使用界面模板生成后，将 CSV 样例内容填入模板。
- 成功行确认导入：只勾选解析成功行并确认。
- 导入成功订单应保存生肖年份；如界面无单独选择，使用当前默认生肖年份。
- 失败行不可导入：保留非法号码 `50` 样例，确认失败行不会保存。
- 重复检测：重复导入同一 raw_text，确认历史重复提示。
- 申报人、渠道、地区识别：检查保存后的订单详情字段。

## 6. 拆单助手验收样例

覆盖：

- 输入含中文逗号、顿号、空行、连续空格的文本。
- 点击文本整理，确认拆成多行。
- 点击预览订单，确认成功行和失败行分开显示。
- 勾选成功行并保存，失败行不可保存。
- 保存后在订单详情按申报人、渠道、关键词可查。
- 拆单助手不自动结算，不产生余额流水。
- 拆单助手保存的订单应写入生肖年份；如界面无单独选择，使用当前默认生肖年份。

建议输入：

```text

特码 01 各10；N不中 08,09,10 各100
非法 50 各10
```

## 8. 结算验收样例

样例文件：`docs/samples/settlement_acceptance_cases.md`。

必须覆盖：

- 命中、未中、不支持阻断正式结算。
- 生肖相关结算优先读取订单保存的 `zodiac_year`；旧订单无 `zodiac_year` 时按默认年份兼容并提示人工确认。
- 旧快照兼容：旧快照无返水字段时不崩溃。
- 赔率读取：申报人绑定方案优先，否则默认方案。
- 返水统计：命中、未中、不支持均按已确认口径参与或按配置为 0。
- 统计结算金额：`中奖金额 + 返水金额 - 投注本金`。

记录字段：

| 项目 | 说明 |
| --- | --- |
| 投注本金 | 当前订单明细金额合计 |
| 中奖金额 | 命中项金额 x 赔率，未配置赔率时为 0 并提示 |
| 返水金额 | 有效投注额 x 返水比例 |
| 统计结算金额 | 中奖金额 + 返水金额 - 投注本金 |

说明：中奖金额、返水金额、统计结算金额只是统计，不代表真实付款、收款或入账。

## 9. 复杂玩法结算验收样例

覆盖：

- 平尾：只看 6 个正码尾数，不看特码。
- 二中二：只看 6 个正码，组合全中才 hit。
- 三中三：只看 6 个正码，3 个全中才 hit。
- 三中二：只看 6 个正码，3 个号码中至少 2 个在正码中即 hit。
- 几中几复选复2：动态展开二中二组合。
- 几中几复选复3：动态展开三中三组合。
- 连肖复选：仍待参考软件中奖样例确认，正式结算应显示不支持。
- 正码特 / 特串：仍待参考软件样例确认，不猜规则。

## 10. 订单管理验收

覆盖：

- 查询：按订单号、关键词查询。
- 筛选：地区、状态、日期、申报人、投注类型、中奖情况。
- 详情：查看订单明细、结算快照、返水统计。
- 导出：按当前筛选条件导出订单表格。
- 作废：未结算订单可作废，需原因和二次确认，写操作日志。
- 作废后的结算限制：作废订单不能结算。
- 清空订单已开放为高风险维护入口：必须自动备份、二次确认、原因必填、输入“确认清空订单”，成功后写维护日志。
- 批量删除已开放为高风险维护入口：必须只删除选中订单及对应明细、结算快照，不删除开奖记录、操作日志或设置。

## 11. 调单快照验收

覆盖：

- 特码调单 01-49 风险表。
- 特码调单按生肖表达式折算号码时读取统一生肖年份配置；风险表按页面所选生肖年份统计对应订单，避免跨年份混算。
- 特码最大亏损自动抛出建议。
- 特码抛出输入：`25=100`、`红波大=100`、`合大=50`、`尾1=20`、`1头=20`。
- 特码抛出保存和撤销。
- 连肖调单按生肖组合风险汇总。
- 连肖抛出输入：`龙羊猴=100`、`龙,羊,猴=100`、`龙-羊-猴=100`。
- 连肖抛出保存和撤销。
- 旧版特码 / 连肖调单快照保存。
- 调整记录查看，并显示 active / reversed / reversal / legacy 状态。
- 复制记录详情。
- 导出记录详情。
- 打印文本生成。

边界：

- 调单不是新投注玩法。
- 调单不修改原订单和 order_items 原始金额。
- 调单不自动重新结算。
- 调单不写客户余额、不生成资金流水、不做真实付款 / 收款 / 兑奖入账。
- 撤销不是删除原记录，而是新增 reversal 记录。
- 本阶段复用 `adjustment_records` 的 JSON 快照字段，不要求新增迁移。
- 调单当前仍只按地区汇总，不新增日期、期号、申报人、渠道、订单状态或结算状态筛选。
- 打印文本不调用真实打印机。

风险公式：

| 页面 | 公式 |
| --- | --- |
| 特码 | `risk_amount = potential_payout_amount + rebate_amount - raw_stake_amount` |
| 连肖 | `risk_amount = potential_payout_amount + rebate_amount - raw_amount` |
| 调整后风险 | `adjusted_risk_amount = risk_amount - thrown_amount` |

## 15. 高风险维护与未开放确认

逐项确认已开放的高风险维护入口都受统一保护：

- 清空订单：自动备份、二次确认、原因必填、确认短语、操作日志。
- 清空日志：自动备份、日志归档、二次确认、原因必填、确认短语、清空后保留新维护日志。
- 批量删除：只删除选中订单及对应明细、结算快照；不删除未选中订单、开奖、日志或设置。
- 重置开奖记录：无结算记录时可执行；存在结算记录时阻断。

逐项确认仍未开放：

- 权限 / 登录 / 角色 / 审批。
- 真正修改原订单式调单。
- 连肖复选正式结算。
- 正码特。
- 特串。
- 正式安装包和升级流程。

确认标准：

- 已开放维护入口必须执行业务写入前完成备份、二次确认、原因、确认短语和操作日志。
- 未开放入口隐藏、禁用或仅提示，不执行业务写入。
- 文案说明需要权限、备份、二次确认、操作日志或参考软件样例。

## 16. 明确不纳入产品范围确认

逐项确认当前产品不提供：

- 客户账户。
- 客户余额。
- 余额流水。
- 真实付款。
- 真实收款。
- 真实兑奖入账。
- 真实打印机调用。
- 云同步 / 在线账号。

确认标准：

- 主导航和页面不出现客户账户、客户余额、余额流水入口。
- 订单详情和结算历史不出现真实入账状态。
- 打印相关只生成文本、复制或导出。
- 文档明确这些不作为正式商用必做缺口。

## 17. 验收通过标准

全部满足后方可进入发布候选：

- 全量 `pytest` 通过。
- `pre_release_check` 通过。
- 数据库迁移状态正常。
- 样例录单金额正确。
- 样例订单保存后可查询、筛选、导出。
- 样例结算命中 / 未中 / 不支持结果正确。
