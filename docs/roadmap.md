# 后续路线图

本文给出 Fortune 正式小范围单机商用版后续工作的推荐顺序。

## P0：保持文档和代码状态一致

- 持续同步 README、商用测试范围、功能状态总览、人工验收脚本。
- 每次开放或关闭入口后，更新对应文档和测试。
- 保持 `data/fortune.db` 不进入 Git。

## P1：复杂玩法规则确认

- 继续补充已支持玩法的规则说明。
- 优先确认胆拖、组选、全包等规则不足玩法。
- 规则未确认前，不接入正式结算。

## P2：结算统计口径完善

- 继续补齐赔率配置匹配验收和旧快照兼容测试。
- 保留中奖金额快照。
- 保留返水配置和返水统计口径。
- 返水只作为结算统计项 / 快照字段展示，不入账、不付款、不形成客户余额。

## P3：调单记录审计口径完善

- 当前特码调单 / 连肖调单只保存调单快照。
- 后续完善调整记录查询、导出和人工验收脚本。
- 不做真实修改原订单式调单。

## P4：订单导入收口

- 当前已支持 txt/csv/xlsx、模板、申报人、渠道、历史重复检测和确认导入成功行。
- 后续完善导入失败报告、回滚验收和更多真实样例覆盖。

## P5：高风险维护入口与未开放能力

- 清空订单、批量删除订单、清空日志、重置开奖记录第一阶段已受保护开放：自动备份、二次确认、原因必填、确认短语和操作日志是交付边界。
- 当前仍不是完整权限系统，继续依赖本机管理和操作规范；后续如需角色、审批、授权范围，需要单独设计。
- 真正修改原订单式调单、真实兑奖、余额修改等仍不开放。
- 连肖复选、正码特、特串等规则未确认玩法，需要参考软件样例确认后才接入正式结算。
- 正式安装包和升级流程需要单独冻结发布、备份和回滚策略。

## P6：明确不纳入当前产品范围

- 客户账户不纳入当前产品范围。
- 客户余额不纳入当前产品范围。
- 余额流水不纳入当前产品范围。
- 钱包系统不纳入当前产品范围。
- 支付系统不纳入当前产品范围。
- 真实兑奖入账不纳入当前产品范围。
- 真实支付 / 收款 / 付款不纳入当前产品范围。
- 真实打印机调用、打印机驱动适配、静默打印、打印模板编辑器不纳入当前产品范围；打印能力以文本生成、复制、导出为准。
- 云同步 / 在线账号不纳入当前产品范围。

## P7：发布检查

- 运行 Alembic 空库升级测试。
- 运行全量 pytest。
- 执行打包前只读自检。
- 复核 `data/fortune.db`、临时文件、测试文件不会进入发布包。
