# 功能状态总览

本文记录 Fortune 当前正式小范围单机商用版的功能状态。Fortune 定位为单机记账本、号码录入工具、订单统计工具、开奖核对工具、中奖金额快照工具、返水金额计算工具和结算统计工具。

Fortune 不做客户账户、不做客户余额、不做余额流水、不做真实兑奖入账，不涉及真实资金支付。中奖金额和返水金额都是结算快照 / 统计参考，不代表已经收款、付款或入账。

## 第一版正式结算支持范围

本范围以当前结算引擎真实支持为准，不以录单解析器可识别为准。

### 第一版正式结算支持

- 特码号码、特码生肖、波色、半波、大小、单双、尾数、头数、合数单双、合数大小、五行。
- 连肖 / 多生肖、连尾、N不中 / 不中、六肖中特、平码、包半波、平尾。
- 二中二、三中三、三中二。
- 几中几复选中的 `复2`、`复3`。

### 可录单但暂不支持正式结算

- 连肖复选。
- 平特一肖 / 平特肖作为独立订单类型保存时。
- 二中特。
- 特串。
- 无法归一到当前结算 matcher 的未知或历史玩法。

这些玩法可保存为记账订单，但正式结算必须强提示并阻断；不得写正式结算快照，不得改变订单结算状态。

### 明确不在第一版范围

- 客户账户、客户余额、余额流水、真实收付款、真实兑奖入账。
- 真实打印机调用、打印机驱动适配、静默打印、打印模板编辑器。
- 规则未确认的独立名义胆拖、拖码、组选、全包、正码特等复杂玩法正式结算。

## 复杂玩法边界

| 玩法 | 状态 | 说明 |
| --- | --- | --- |
| N不中 / 不中 | 已对齐 | 保存为一条整组订单，金额按整组金额；结算口径为全部开奖号码均未出现才命中。 |
| 连肖 | 已对齐 | 保存为一条整组订单，金额不按生肖个数或生肖下号码数相乘；结算沿用当前支持范围。 |
| 几中几复选 | 已支持第一阶段 | 按组合数 `C(n,k)` 计算总额；`复2` 按二中二组合结算，`复3` 按三中三组合结算。 |
| 连肖复选 | 录单金额预览已支持 | 按组合数 `C(n,k)` 计算总额；正式结算仍显示不支持，等待参考软件中奖样例。 |
| 二中二 / 三中三 / 三中二 | 已支持第一阶段 | 单组总额 = 金额，多组或拖式总额 = 金额 x 组合组数；正式结算只看 6 个正码，不看特码。 |
| 平尾 | 已支持第一阶段 | 金额按尾数个数计算；正式结算只看 6 个正码尾数，特码不参与。 |
| 正码特 / 特串 | 待补样例 | 更新日志明确存在但缓存无样本，本阶段不猜规则。 |
| 独立名义的胆拖、组选、全包 | 正式结算未开放 | 底层能力已按复选、连码组合和二中二拖式 / 分组组合覆盖；不新增独立资金玩法名。 |

## 调单正式功能第一阶段口径

- 特码调单按 01-49 生成风险表，展示号码、生肖、投注折算金额、预计赔付、原始风险、已抛出和调整后风险；生肖折算读取统一生肖年份配置，并按页面所选生肖年份统计对应订单，避免跨年份混算。
- 特码调单最大亏损建议公式：`throw_amount = adjusted_risk_amount - max_loss`，仅当 `adjusted_risk_amount > max_loss` 时生成，输出格式为 `号码=金额`。
- 特码抛出输入支持 `25=100`、多行 / 逗号分隔，以及部分语义展开：红波大、红波小、红单、蓝双、合大、合小、合单、合双、尾1、1头等。
- 连肖调单按生肖组合汇总风险；同一组合按固定生肖顺序归一，普通连肖一组为一注，不按生肖个数乘金额。
- 连肖抛出输入支持 `龙羊猴=100`、`龙,羊,猴=100`、`龙-羊-猴=100`。
- 抛出记录写入 `adjustment_records` 的 JSON 快照字段，类型为 `special_throw` 或 `lianxiao_throw`；撤销写入新的 reversal 记录，类型为 `special_throw_reversal` 或 `lianxiao_throw_reversal`，不删除原记录。
- 调单记录通过事件流计算 active / reversed / reversal / legacy 状态；本阶段复用现有 JSON 快照字段，不为调单快照新增迁移。
- 风险统计公式：特码 `risk_amount = potential_payout_amount + rebate_amount - raw_stake_amount`；连肖 `risk_amount = potential_payout_amount + rebate_amount - raw_amount`；调整后风险为 `risk_amount - thrown_amount`，允许显示负数。
- 调单当前仍只按地区汇总，不新增日期、期号、申报人、渠道、订单状态或结算状态筛选。

## 生肖年份验收口径

- 号码大全的十二生肖号码按所选开奖年份显示，不再显示旧版静态年份提示。
- 正式验收前必须确认当前开奖年份；切换年份会影响生肖投注展开、生肖相关结算和特码调单按生肖折算号码。
- 本口径不修改订单原始金额、中奖金额公式、返水公式或调单风险公式，也不涉及客户余额、付款、收款或入账。

## 高风险维护入口保护口径

清空订单、批量删除订单、清空日志、重置开奖记录不再作为普通禁用项处理，当前第一阶段已经开放为受保护维护入口。统一保护要求：操作前自动备份 `data/fortune.db`，弹出二次确认，展示影响范围和数量，原因必填，确认短语必须匹配，成功后写 `maintenance` 模块操作日志；任何失败都应阻断并避免半完成状态。重置开奖记录在存在 `settlement_records` 时阻断。
