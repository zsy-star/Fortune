# 小范围商用测试前验收清单

本文档供测试人员在正式交给业务同事试用前逐项验收。每项均包含：验收目标、操作步骤、预期结果、失败时处理建议。

测试前请准备：

- 独立测试数据库（不要使用生产 `data/fortune.db`）
- 可正常启动 Fortune 的 Python 环境
- 至少一条可解析的正常录单文本、一条故意写错的异常录单文本
- 至少一条可用于结算预览的开奖记录（澳门或香港，期号与订单地区一致）

---

## 1. 录单验收

**验收目标**
确认「我要录单」弹窗能正确解析、预览并保存订单，异常输入不会写入脏数据。

**操作步骤**

1. 启动软件，点击顶部「我要录单」。
2. 在文本区粘贴一条正常特码订单，例如：`澳门 特码 01=10`。
3. 等待自动解析，检查下方预览表格是否出现对应明细。
4. 点击「保存订单」，记录返回的订单号。
5. 再粘贴一条无法解析或格式明显错误的文本，尝试保存。

**预期结果**

- 正常订单解析成功，预览表格字段（区域、投注类型、号码、金额）正确。
- 保存成功后提示成功，且可在订单详情中查到该订单。
- 异常订单保存被阻止，界面给出明确警告，数据库中不应新增无效订单。

**失败时处理建议**

- 解析失败：核对文本格式是否符合当前支持的特码录入规则，参考录单窗口底部提示。
- 保存失败：查看状态栏或弹窗错误信息；检查数据库是否可写、是否被其他程序占用。
- 记录失败样例文本、截图和订单号，反馈给开发人员，不要继续批量录入。

---

## 2. 订单查询验收

**验收目标**
确认订单详情页能按条件查询、分页展示真实数据库中的订单。

**操作步骤**

1. 进入「订单详情」页。
2. 使用地区、日期、状态等筛选条件查询刚保存的订单。
3. 点击列表中的订单，查看右侧或下方明细区域。
4. 翻页测试（若数据量足够）。

**预期结果**

- 刚保存的订单能被查到，订单号、地区、状态、金额与录单一致。
- 明细列表展示投注类型、选项、金额等字段。
- 分页切换正常，无空白闪退。

**失败时处理建议**

- 查不到订单：确认是否使用了正确的筛选条件；刷新页面后重试。
- 明细为空：检查该订单保存时是否真的写入了明细。
- 记录筛选条件和订单号后暂停测试，避免在错误数据上继续结算。

---

## 3. 开奖记录验收

**验收目标**
确认今日开奖、开奖历史页能读取本地开奖库，手动录入或同步后数据可用于结算。

**操作步骤**

1. 进入「今日开奖」页，查看澳门、香港最新开奖展示。
2. 若无数据，使用页面提供的刷新/同步功能，或确认数据库中已有对应期号记录。
3. 进入「开奖历史」，按期号或地区筛选，确认记录完整（普通号 + 特码）。
4. 记录一条与待结算订单同地区、同（或可用）期号的开奖记录 ID 或期号。

**预期结果**

- 页面展示真实数据库中的开奖数据，不显示编造的假号码。
- 同步或录入成功后，历史列表可查到对应期号。
- 号码、生肖、波色等展示无乱码。

**失败时处理建议**

- 无开奖数据：先完成开奖录入或同步，再进行结算相关测试。
- 同步失败：检查网络；查看操作日志是否有采集失败记录。
- 期号与订单不匹配：更换匹配期号或重新录单，不要强行结算。

---

## 4. 结算预览验收

**验收目标**
确认结算预览为只读操作，能正确展示命中/未命中/不支持，且不修改订单状态。

**操作步骤**

1. 在「订单详情」选中一条待处理订单。
2. 点击「结算预览」，选择与订单地区匹配的开奖期号。
3. 查看预览结果：每条明细的中奖判定与原因说明。
4. 关闭预览窗口，回到订单详情，确认订单状态仍为待处理。

**预期结果**

- 预览窗口展示开奖号码、特码及每条明细判定结果。
- 支持的玩法能区分「中奖」「未中奖」；暂不支持的玩法标记为「不支持」并说明原因。
- 预览前后订单状态不变，无结算流水新增。

**失败时处理建议**

- 提示缺少开奖：先完成第 3 项开奖记录验收。
- 预览报错：记录订单号、期号、错误弹窗全文。
- 判定与预期不符：保留订单原文、开奖号码截图，供开发核对规则。

---

## 5. 正式确认结算验收

**验收目标**
确认正式结算需二次确认，成功后更新订单状态并产生可追溯记录。

**操作步骤**

1. 对同一条已预览过的待处理订单，再次打开结算预览。
2. 在预览窗口点击「正式确认结算」（或等效按钮）。
3. 在二次确认对话框中确认执行。
4. 返回订单详情，检查订单状态是否变为已结算。
5. 进入「结算历史」验证是否出现对应流水（见第 6 项）。

**预期结果**

- 未确认前不会写入结算结果。
- 确认成功后订单状态更新为已结算。
- 操作日志中有结算相关记录（见第 8 项）。

**失败时处理建议**

- 重复结算：已结算订单应被拒绝再次确认；若可重复结算则为严重缺陷，立即停止试用。
- 结算失败：记录错误信息，不要手动改数据库。
- 部分明细不支持：确认界面是否明确提示，且不会错误标记为已结算。

---

## 6. 结算历史 / 流水验收

**验收目标**
确认结算历史页只读展示已结算流水，筛选与导出入口可用。

**操作步骤**

1. 进入「结算历史」页。
2. 按日期、地区等条件筛选，定位刚结算的订单流水。
3. 核对订单号、结算时间、开奖期号、判定摘要等字段。
4. 确认页面提示为只读，无「重新结算」「修改状态」类按钮。

**预期结果**

- 刚完成的结算出现在列表中，信息与预览一致。
- 页面明确标注只读，不会误触修改数据。
- 作废订单不应出现在正常结算流水中（若有作废订单可交叉验证）。

**失败时处理建议**

- 找不到流水：确认结算是否真正成功；检查日期筛选范围。
- 数据与预览不一致：记录订单号并停止该订单的后续操作。

---

## 7. 订单作废验收

**验收目标**
确认待处理订单可作废且需填写原因；已结算订单不能作废。

**操作步骤**

1. 新建或使用一条「待处理」订单，在订单详情点击「作废订单」。
2. 输入作废原因并确认。
3. 确认订单状态变为已作废，且不再参与正常结算统计。
4. 选中一条「已结算」订单，尝试作废。

**预期结果**

- 待处理订单作废成功，状态更新，操作日志有记录。
- 已作废订单不能重复作废。
- 已结算订单作废被阻止，并给出明确提示。

**失败时处理建议**

- 作废后仍出现在可结算列表：停止测试并报告。
- 已结算可被作废：视为严重缺陷，立即上报。

---

## 8. 操作日志验收

**验收目标**
确认关键业务操作（录单、结算、作废、备份、恢复、导出等）均写入操作日志且可查询。

**操作步骤**

1. 进入「操作日志」页。
2. 按日期范围查询，定位本次测试产生的录单、结算、作废、备份等记录。
3. 检查模块、动作、操作人/来源、时间、摘要等字段是否合理。
4. 尝试导出操作日志 Excel（见第 11 项）。

**预期结果**

- 上述操作均有对应日志，时间顺序合理。
- 日志内容为真实操作摘要，非假数据占位。
- 页面为查询/导出用途，不提供「清空日志」入口（当前测试版未开放）。

**失败时处理建议**

- 缺少关键操作日志：记录缺失的操作类型与时间，反馈开发。
- 日志乱码：检查系统区域与字体配置。

---

## 9. 数据库备份验收

**验收目标**
确认可在辅助工具中创建数据库备份，备份文件落在 `data/backups/` 且可追溯。

**操作步骤**

1. 进入「辅助工具」页，找到「数据库备份 / 恢复」区域。
2. 点击「立即备份」。
3. 查看成功提示中的备份文件名与路径。
4. 点击「刷新备份列表」，确认新备份出现在列表中。
5. 在文件管理器中确认 `data/backups/` 下存在对应 `.db` 文件。

**预期结果**

- 备份成功提示包含文件名、大小、路径。
- 备份列表展示创建时间、大小、备份原因等。
- 操作日志中有 backup 记录。

**失败时处理建议**

- 备份失败：检查磁盘空间与目录写权限。
- 列表不刷新：手动刷新；若仍无记录，检查 backups 目录权限。

---

## 10. 数据库恢复验收

**验收目标**
确认从备份恢复需二次确认，恢复前自动备份当前库，恢复后提示重启。

**操作步骤**

1. 在备份列表中选择较早的备份（建议使用测试库）。
2. 点击「从备份恢复」，阅读确认对话框全文。
3. 确认执行恢复。
4. 查看成功提示中的恢复来源与「恢复前自动备份」路径。
5. 重启软件，抽查订单/开奖数据是否与恢复点一致。

**预期结果**

- 恢复前有明确风险警告和二次确认。
- 恢复前系统自动备份当前数据库。
- 恢复成功后提示建议重启；重启后数据与所选备份一致。

**失败时处理建议**

- 恢复失败：当前库应保持不变；查看错误提示，勿反复点击。
- 恢复后数据异常：使用「恢复前自动备份」回滚，并报告问题。

---

## 11. Excel 导出验收

**验收目标**
确认订单、结算流水、操作日志均可导出为 `.xlsx`，且导出过程不修改数据库。

**操作步骤**

1. 在「订单详情」点击「导出 Excel」，选择空目录（勿选生产 exports 目录）。
2. 打开生成的文件，核对列名与数据条数。
3. 在「结算历史」导出 Excel，核对已结算记录。
4. 在「操作日志」导出 Excel，核对日志条数。
5. 导出前后对比数据库文件修改时间（应无业务性写入）。

**预期结果**

- 三个导出入口均成功，文件名含时间戳或类型标识。
- Excel 可正常打开，中文无乱码，数据与界面一致。
- 导出仅为读取操作，不改变订单/结算状态。

**失败时处理建议**

- 导出失败：确认目标目录可写；检查 openpyxl 是否安装。
- 文件为空：确认筛选条件下确有数据。

---

## 12. 异常处理验收

**验收目标**
确认常见错误以友好提示呈现，程序不崩溃、不 silently 失败。

**操作步骤**

1. 对不存在的订单尝试结算预览（若可构造）。
2. 在无开奖数据时尝试结算预览。
3. 备份时模拟目标目录不可写（可选，测试环境）。
4. 导出到无权限目录（可选）。
5. 观察每次错误是否有弹窗或状态栏提示。

**预期结果**

- 错误信息为中文、可理解，指明原因或下一步建议。
- 主窗口保持可用，无需强制结束进程。
- 不会因单次操作失败导致后续功能全部不可用。

**失败时处理建议**

- 程序崩溃或无响应：记录操作步骤与 Windows 事件日志，停止试用。
- 错误信息为空：截图并反馈。

---

## 13. 防误操作验收

**验收目标**
确认高风险操作均有确认步骤，只读页面不会误改数据。

**操作步骤**

1. 验证正式确认结算、数据库恢复、订单作废均有二次确认。
2. 验证结算历史、操作日志、数据总览无修改/删除按钮。
3. 验证未开放功能（连码调单、拆单助手等）入口禁用或明确标注「暂未开放」。
4. 尝试对已结算订单再次确认结算。

**预期结果**

- 高风险操作取消后无任何数据变更。
- 只读页面无隐藏写操作。
- 未开放功能不可误触写入业务库。

**失败时处理建议**

- 发现可绕过确认的写操作：立即停止使用并报告。
- 未开放入口仍可写入：按缺陷处理，暂停商用。

---

## 14. 数据库文件安全验收

**验收目标**
确认测试与交付流程不会误提交、误打包真实业务数据库。

**操作步骤**

1. 确认试用环境使用独立 `fortune.db` 或测试副本，而非生产库。
2. 运行 `python scripts/pre_release_check.py --project-root .`（只读），查看是否有 `.xlsx`、临时测试目录等警告。
3. 确认 Git 工作区未跟踪 `data/fortune.db`、`data/backups/`、`exports/` 下的业务文件。
4. 确认备份文件命名含时间戳，恢复前自动备份路径可识别。

**预期结果**

- 生产/试用真实数据与源码仓库隔离。
- 自检脚本仅报告、不删除任何文件。
- 备份策略可追溯，误操作可回滚。

**失败时处理建议**

- 若真实库已被提交：不要 push，联系开发从版本库移除并轮换敏感数据。
- 自检脚本报失败项：按 `docs/pre_packaging_checklist.md` 逐项处理后再打包。

---

## 15. 小范围试用前注意事项

**验收目标**
测试负责人确认团队已理解试用边界与应急流程。

**操作步骤**

1. 向试用人员说明当前仅保证特码类录入与结算稳定，其他玩法可能不支持结算。
2. 说明每日或每批次操作后应执行备份。
3. 说明出现问题时保留：订单号、期号、截图、操作日志导出文件。
4. 说明不要多人同时操作同一数据库文件（SQLite 本地单文件限制）。
5. 对照 `docs/commercial_test_scope.md` 确认未开放功能不向业务人员展示为可用。

**预期结果**

- 试用人员知晓功能边界、备份要求、问题上报方式。
- 试用数据与生产数据物理隔离。
- 验收表（可打印 `docs/manual_test_script.md`）全部勾选或注明例外项。

**失败时处理建议**

- 任一核心项（录单、结算、备份恢复、防误操作）未通过：不得进入小范围商用，先修复再复测。
- 非核心项（如图表样式）可记录为已知问题，但不影响记账准确性项必须为零缺陷。
