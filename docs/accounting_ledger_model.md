# 账务 / 余额流水模型

本文冻结 Fortune 后续开放真实兑奖、余额流水、客户账户、返水和佣金前的账务设计口径。当前只作为设计约束，不代表功能已经实现。

## 当前状态

- 当前版本状态为：商用测试版 / 内部试用版。
- 当前已支持基础中奖金额快照。
- 当前不写余额。
- 当前不做客户账户。
- 当前不做返水 / 佣金。
- 当前不做真实盈亏。
- 当前不开放真实兑奖。

## 未来核心对象设计建议

| 对象 | 建议职责 |
| --- | --- |
| 客户账户 | 保存客户身份、账户状态和当前余额摘要。 |
| 余额流水 | 记录所有余额变动，作为余额变动的唯一事实来源。 |
| 结算记录 | 保存订单结算结果、命中明细和中奖金额快照。 |
| 订单记录 | 保存原始订单事实，不因调单或余额入账而直接覆盖。 |
| 返水记录 | 保存未来返水计算结果和入账来源。 |
| 调整记录 | 保存调单快照、调整原因和未来可能的冲正依据。 |
| 审计记录 | 保存中高风险操作的操作人、原因、前后摘要和确认信息。 |

## 余额流水类型建议

- 投注扣款。
- 中奖入账。
- 返水入账。
- 手工加款。
- 手工扣款。
- 作废回滚。
- 结算冲正。
- 调单调整。
- 系统修正。

## 账务原则

- 余额不能直接覆盖，只能通过流水变动。
- 每笔流水必须可追溯来源。
- 已结算订单不能重复入账。
- 作废已入账订单必须走冲正流水。
- 赔率修改不能 retroactively 改旧结算，除非走冲正。
- 调单不直接改历史订单，必须生成调整记录或冲正记录。
- 所有金额使用 `Decimal`。
- 禁止 `float`。
- 余额变动必须事务化。

## 与现有系统关系

- `SettlementRecord` 目前保存中奖金额快照。
- 未来余额入账应基于 `SettlementRecord` 快照。
- `OperationLog` 记录行为审计。
- `AdjustmentRecord` 当前只是调单快照，不影响余额。
- `Order` 当前是订单事实来源。
