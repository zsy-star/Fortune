## 已确认规则

### 特码号码 / 生肖 / 多生肖

**证据来源：**

- `last_order_data.json` 行 0-5：`特码`，计算方式 `各数`，如 `蛇` 金额 20 总额 80；`25-37-49` 金额 20 总额 60。
- 多个生肖样例：行 23 `虎-蛇-猴-猪` 金额 10 总额 160；行 51 `牛-虎-狗-羊-猪` 金额 230 总额 4600。

**识别格式：**

- 号码可保存为单号或 `-` 分隔号码列表。
- 生肖可保存为单个生肖或 `-` 分隔生肖列表。

**投注类型：** `特码`

**计算方式：** `各数`

**金额计算：**

- 号码按号码个数计算：`订单总额 = 金额 x 号码个数`。
- 生肖按该生肖在当年对应号码个数计算，2026 年马为 5 个号，其余生肖多为 4 个号；多生肖按展开后的号码总数计算。
- 重复号码会计入总额。行 93 `44-06-44-22-44` 金额 10，总额 50。

**结算口径：**

- 样例仅能确认保存金额口径；特码号码/生肖实际中奖规则需结合开奖上下文确认。

**Fortune 当前差距：**

- Fortune 已支持号码、生肖、波色、半波、大小、单双、尾数、头数、合数、五行等基础特码解析和结算。
- Fortune 表格录入会把多号码拆成多个订单明细；参考样例中多号码通常保存为一条汇总行，展示形态不同。

1. `N不中`：参考样例清楚显示整组金额，Fortune 已有结算基础，风险较低。
2. `几中几复选` / `连肖复选` 的金额预览：组合数公式证据充分，但先只做解析预览和测试设计，不直接接结算。
3. `连肖` 金额保存口径：参考样例显示总额=金额，需要先确认 Fortune 当前“按号码展开”的行为是否应改。
4. `平码` 多命中赔付：已有少量中奖金额样例，但需开奖上下文确认。
5. `平特一肖` / `平特一肖带主肖`：业务价值高，但结算口径风险较大，应先补充开奖样例。
6. `二中二` / `三中三` / `三中二`：金额保存基本明确，结算规则复杂，等赔率和开奖样例。
7. `包半波`、`连尾`、`六肖中特`：Fortune 已有简化支持，但本轮参考样例不足，暂不调整。
8. `胆拖`、`拖码`、`组选`、`全包/包号`：证据不足，暂不实现。

## 需要用户补充的样例

- 每个待确认玩法请提供：原始输入、识别结果截图或导出的订单行、投注类型、订单信息、复选类型、计算方式、金额、订单总额、中奖情况、中奖金额。
- 胆拖/拖码：至少 3 条，覆盖一个胆码多个拖码、多个胆码多个拖码、非法或边界号码。
- 组选：至少 3 条，覆盖不同号码个数和金额。
- 全包/包号：至少 2 条，确认是否展开 49 号和投注类型显示。
- 包半波：至少 3 条，覆盖 `红单`、`红大`、多个半波组合。
- 连尾：至少 3 条，覆盖 0 尾、2 连尾、5 连尾。
- 平码/平尾/平特一肖：需要带同期开奖号的中奖样例，用于确认多命中计奖。
